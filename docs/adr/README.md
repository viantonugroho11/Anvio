# Architecture Decision Records

ADRs record **why** the architecture is the way it is. Numbers are stable and never reused. A decision that changes gets a new ADR; the old one is marked superseded or amended and keeps its original text.

**Status values:** PROPOSED · ACCEPTED · SUPERSEDED · DEPRECATED · REJECTED.

**Reconciliation (2026-10-25).** Every ADR was checked against the current code. Where code and ADR diverge, or the ADR carried no status, a dated _Reconciliation note_ was appended at the end of the ADR. Decision text was not rewritten. A PROPOSED ADR stays PROPOSED even when the code implements it: acceptance is an owner decision, not something inferred from code.
