# 05 — Regression Fixes

Every defect followed the same steps: reproduce it with a failing test, find the root cause, fix it, rerun the test (now passing) and rerun the full suite. No assertion was weakened and no test was disabled. Two test assertions were _tightened_ after their fix landed:

- FI-11 used to accept "failed **or** an event"; it now requires a `failed` status, the exact error and a user-visible notice.
- FI-06 now requires the real parse error.

"Regression" in the prompt's sense means a defect present after the refactoring. Some of these predate PR #117 and were simply never exercised end to end before; the column says which.

## Untested parts of fixes

- PR-01: the `MAX_MIXTURE_AGENTS = 8` rejection path has no dedicated test.
- PR-12: no test asserts the timer is unref'd.
- PR-15: the repair runs on every worker start, in **any** process that calls `registerGatewayWorker`. In a multi-process deployment where a second worker starts while the first is mid-turn, the second marks that live session `failed` (see R-03). Level 1 is single-process, so this does not apply there.
