# 07 — Remaining Risks

## New in this phase (found, not fixed)

| ID   | Risk                                                                                                                             | Evidence                                                                                                         | Impact                                                                                            | Recommendation                                                                                                                                                                              |
| ---- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-01 | `platform.shutdown()` neither drains nor aborts turns in flight. Turns queued behind the concurrency cap are held only in memory | LOAD-04: 8 model calls still running after shutdown returned; 2 queued sessions `idle`, messages never processed | On deploy or restart, in-flight turns are reported failed (PR-15) and queued messages are lost    | Track active runs in the worker; on shutdown, stop accepting, wait up to a grace period, then `runtime.stop` each one. Persist queued requests (Level 2) or reject them with a retry notice |
| R-02 | Level 1 throughput ceiling of about 90–200 turns/s on this machine, dominated by filesystem syscalls                             | [03](03-concurrency-performance.md)                                                                              | Fine for one team; not for high fan-in channels                                                   | Fewer session rewrites per turn (status updates could stay in memory until done); recommend Level 2 for busy workspaces                                                                     |
| R-03 | `repairInterruptedSessions` runs in every process that registers the gateway worker                                              | Code review of PR-15                                                                                             | Multi-process topologies: a second worker starting marks the first worker's live session `failed` | Record the owning PID or instance ID in session metadata and repair only stale owners; or repair only under a workspace lock                                                                |
| R-04 | Tool calls within one model round run sequentially                                                                               | `packages/agents/src/tool-round.ts`                                                                              | Latency is the sum of tool latencies for independent calls                                        | Run read-only, side-effect-free tools concurrently behind a policy flag                                                                                                                     |
| R-05 | First message of a new channel thread still scans all session files                                                              | PR-18 design (correct across processes)                                                                          | O(N) once per new thread                                                                          | A persisted thread index file, or Level 2                                                                                                                                                   |
| R-06 | The gbrain memory MCP client is created in `createPlatform` but not closed on shutdown                                           | Code review while fixing PR-17                                                                                   | Orphan `gbrain` process when `memory.provider: gbrain`                                            | Add it to the `mcp servers` shutdown step                                                                                                                                                   |
| R-07 | The agent Markdown body is not used as the system prompt (the persona is)                                                        | E2E-10 investigation                                                                                             | Docs and behaviour disagree, and users edit the wrong file                                        | Decide which one is right; then fix the loader or CLAUDE.md and the docs                                                                                                                    |
| R-08 | SOUL.md approver IDs only recognise slack/telegram/whatsapp/discord/cli                                                          | MCP-02/03 setup                                                                                                  | webchat, rest and email users cannot approve                                                      | Extend the parser, or document it                                                                                                                                                           |
| R-09 | `MAX_MIXTURE_AGENTS` rejection and the PR-12 timer `unref` have no dedicated tests                                               | [05](05-regression-fixes.md)                                                                                     | Could regress unnoticed                                                                           | Add the two unit tests                                                                                                                                                                      |
