# 06 — Production Readiness

Classification: **READY** · **READY WITH CONDITIONS** · **NOT READY** · **NOT VERIFIED**.

A rating is about what was _verified_ in this phase. A NOT VERIFIED area may work perfectly well; it was simply not proven here.

## Overall

**READY WITH CONDITIONS** for a single-process Level 1 deployment (`anvio gateway start` or the CLI) with one LLM provider, once that provider has been smoke-tested live by the operator. Every other topology or integration is NOT VERIFIED.

## Deployment conditions (READY WITH CONDITIONS)

1. Run **one** Anvio process per workspace directory.
2. Before go-live, smoke-test each configured model provider and channel live. The tests in this repo do not cover them.
3. Do not run with `NODE_TLS_REJECT_UNAUTHORIZED=0`. It was set in this verification machine's shell and silently disables TLS checks for every provider call.
4. Expect turns in flight at restart to be reported as failed, and expect queued messages to be dropped. Tell users to resend after a deploy, or drain traffic before stopping.
5. Keep `ANVIO_MAX_CONCURRENT_RUNS` within the provider's rate limit. The cap is enforced exactly.
6. Do not set `ANTHROPIC_API_KEY` together with `runtime.provider: claude-code` (CLAUDE.md, two auth layers).
