## Apakah satu ekstensi yang gagal dapat menjatuhkan runtime?

| Jalur                                    | Dapat menjatuhkan proses?                                               | Catatan                                                                                |
| ---------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Proses MCP stdio crash                   | Tidak                                                                   | Proses terpisah; error ditangani per request                                           |
| Proses MCP menulis stdout sampah         | Tidak (Unverified penuh)                                                | Parser framing mengabaikan/menunggu header                                             |
| Promise ekstensi tanpa catch             | **Tidak lagi** setelah T-005 (guard `unhandledRejection` di entrypoint) | PR #112                                                                                |
| `uncaughtException` dari kode in-process | **Ya** (sengaja: exit)                                                  | Plugin in-process yang throw secara sinkron di callback timer akan menghentikan proses |
| Ekstensi menggantung tanpa timeout       | Ya, secara fungsional                                                   | Turn agent menggantung → via P2-CH-01 channel ikut tertahan                            |

## Rekomendasi

1. Hapus fallback stub di jalur produksi (G-26); server gagal → status `unhealthy`, tool tidak diiklankan, log WARN.
2. Health check periodik + circuit breaker per server MCP / remote A2A (pola `ProviderCircuitBreaker` yang sudah ada di `packages/models`).
3. Timeout & retry dengan jitter untuk `a2a_delegate`; teruskan `timeoutMs` dari config.
4. Plugin in-process: semua callback plugin dibungkus guard (pola `runGuarded` dari T-005); exception sinkron di registrasi → plugin ditandai `failed`, bukan crash boot.
5. Status plugin (`installed/enabled/failed/quarantined`) + alasan tersimpan dan terlihat di `anvio plugins list`.
