# 02 — Agent Core Comparison

## 1. Dua filosofi

| Aspek       | Anvio                                                                                                                                              | Slaude                                                                                                                                                            |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Otak agent  | **Loop sendiri** (`packages/agents/src/runtime.ts`, ≤5 iterasi) + opsi delegasi ke runtime vendor (`packages/runtimes`, termasuk Claude Agent SDK) | **Sepenuhnya Claude Agent SDK** (`src/agent/manager.ts:17,1285` `agentSdk.query({prompt, options})`)                                                              |
| Provider    | 18 provider via `ModelProvider`                                                                                                                    | "Any Anthropic-compatible API" (`ANTHROPIC_BASE_URL` + key, `SLAUDE_MODEL`)                                                                                       |
| Bentuk sesi | Turn = satu `stream()`; history dibangun ulang tiap turn dari memory                                                                               | **Sesi SDK hidup** (`LiveSession`): prompt async-iterable, pesan baru di-push ke sesi yang sama (`pushUser`), idle TTL menutup loop, resume saat pesan berikutnya |

| Loop eksekusi              | Milik sendiri, budget 5 (G-03)                                                                                                      | SDK (tanpa batas iterasi eksplisit dari Slaude)                                                               | Slaude mewarisi loop matang; Anvio harus memperbaiki sendiri          |

## 3. Tradeoff

| Dimensi                | Loop sendiri (Anvio)               | SDK (Slaude)                                                                                                                 |
| ---------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Ketergantungan vendor  | Rendah                             | Tinggi — loop, kompaksi, tool, MCP, plugin bergantung CLI Claude Code                                                        |
| Fleksibilitas provider | Tinggi (OpenAI, Gemini, Ollama, …) | Hanya API Anthropic-compatible                                                                                               |
| Otonomi                | Terbatas (5 iterasi)               | Tinggi (loop CLI)                                                                                                            |
| Ekstensibilitas        | Port-based, multi-runtime          | Lewat ekosistem Claude Code (plugin, skill, MCP)                                                                             |
| Keandalan eksekusi     | Lemah di state/cancel/recovery     | Kuat (loop teruji vendor + antrean HA buatan sendiri)                                                                        |
| Lock-in                | Rendah                             | Tinggi; perubahan perilaku SDK merembet (field notes Slaude mencatat beberapa "LANDMINE" SDK, mis. `config/plugins.ts:9-12`) |

## 4. Rekomendasi

- **Jangan mengganti otak Anvio dengan SDK.** Anvio sudah memilikinya sebagai **runtime opsional** (`runtime.provider: claude-code`). Mengganti core akan menghilangkan 17 provider lain dan runtime vendor lain tanpa manfaat yang tidak bisa dicapai dengan memperbaiki loop (G-03, G-08, G-10) — perbaikan itu kecil–menengah dan sudah ada di backlog.
- **Adopsi pola di sekitar SDK**, bukan SDK-nya: sesi hidup dengan idle TTL untuk runtime vendor (mengurangi biaya resume per turn), `AbortController` per sesi, child-env scrub, lock sesi.
- Runtime `claude-code` Anvio sudah memakai `canUseTool` bila harness aktif (`claude-code-runtime.ts:230`). Child env-nya hanya menghapus key Anthropic (`claude-code-auth.ts:60-67`) — `OPENAI_API_KEY`, `ANVIO_CREDENTIALS_PASSPHRASE`, token channel tetap terlihat oleh tool Bash di sesi Claude Code. Ini jalur bocor yang sama dengan G-06 dan harus ikut T-007.
